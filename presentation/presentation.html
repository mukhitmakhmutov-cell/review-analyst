Review Analyst
Гибридный проект ML + AI: анализ тональности отзывов
Проблема

Бизнес получает тысячи отзывов, но не может быстро понять, что именно не так и что делать.

Решение

Мультиязычная ML-модель (EN/RU/KZ) классифицирует каждый отзыв (негатив / нейтрал / позитив), а LLM превращает негатив в готовый бизнес-отчёт с конкретными рекомендациями.

Ключевые наблюдения
•  EN: 1–2★ → негатив, 3★ → нейтрал, 4–5★ → позитив; классы сбалансированы
•  RU: 90k товарных отзывов (rureviews) + общедоменные (рестораны/организации)
•  KZ: только 1 250 открытых отзывов (развлечения) — большие датасеты gated
•  RU test — только общедоменные отзывы: это реальный сценарий приложения

Демо

FastAPI + веб-интерфейс · загрузка файла → ML → LLM-отчёт

Как это работает

1.  Пользователь вставляет отзывы или перетаскивает файл (.txt/.csv/.jsonl/.json)

2.  ML-модель классифицирует каждый отзыв и даёт вероятности

3.  LLM читает негатив и пишет отчёт: жалобы + рекомендации

4.  Всё рендерится в браузере (Markdown)

Выводы и что дальше

Что получилось
•  Рабочая модель: fine-tuned мультиязычный DistilBERT — F1 0.764 overall, RU 0.814
•  Гибридный продукт: ML-классификация (EN/RU/KZ) + LLM-отчёт на русском
•  Веб-интерфейс: файлы, ручной ввод, генерация примера через LLM
Что было сложно
•  Обычный MLM-трансформер схлопывал всё в «нейтрал» — спасла sentiment-база + её голова
•  LLM — thinking-модель: без отключения «размышлений» content приходит пустым
•  KZ: открытых бизнес-отзывов нет — только 1 250 (развлечения), метрики завышены
Что улучшил бы при большем времени
•  Больше KZ-данных (бизнес-домен) и более крупная модель для нюансов (ирония, отрицание)
•  RAG: LLM ссылалась бы на базу знаний о заведении
